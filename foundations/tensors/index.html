张量与形状导数与损失训练循环SFT 与 LoRA偏好学习量化与推理

本课学完，你能做什么

  • 用形状说明每一维代表什么
  • 从最右边对齐，判断广播是否成立
  • 算出按列加偏置的结果，并发现静默扩成错误形状的风险

把张量想成有格子的收纳架。一个数像一件物品，一串数像一层架子，多层架子还能组成仓库。形状是每层有多少格、共有多少层的说明，不是格子里的具体数值。

一个数、一串数、一张表

张量是按规则排列的数值。标量形状是 ()；3 个数的一维张量形状是 (3,)；2 行 3 列的二维张量形状是 (2, 3)。形状的长度叫维数，所有维度大小相乘得到元素数量。Python 列表只是本课用来模拟这些数字，不能代替张量库的 dtype、设备与运算语义。

[[1,2,3],[4,5,6]] 有 2×3=6 个数。形状不是 (6,)，因为行列关系仍然存在。

维度名字比数字更重要

文本模型常把数据安排成 (batch, sequence, hidden)：几条样本、每条几个位置、每个位置几个特征。batch 是一批样本的数量。相同的 (2,3) 可以表示两条样本各有三个特征，也可以有别的含义；写注释说明每一维，才能检查运算是不是在正确的轴上。

(2,3,4) 有 24 个元素；这里 2 是样本数，3 是位置数，4 是特征数。reshape 改排列视图或布局，不会凭空增加元素，也不会自动证明语义正确。

广播：从最右边一维一维对齐

广播用于逐元素运算：从右向左比较，对应大小相等、其中一个为 1，或者某一边没有这一维时才允许扩展。少的维度可先在左边补 1，再把大小为 1 的维扩成另一边的大小。它不是任意重复列表；乘法 @ 的矩阵相乘规则也不是这条逐元素相加规则。

(2,3)+(3,)：把后者视为 (1,3)，结果为 (2,3)。每行分别加同一组 3 个偏置。(2,3)+(2,) 的最右边是 3 对 2，不能广播。

能运行，也可能算错了目标

代码不报错不代表计算符合业务。比如预测值 (2,1) 减标签 (2,) 会广播成 (2,2)，变成每个预测值与每个标签都比较。若原意是逐样本比较，应把两边都安排成 (2,1)，并在损失前检查 shape。

检查清单：每一维的名字是什么？输出预计是什么形状？标签与预测是否一一对应？不要靠“元素数量一样”判断。

顺着数字与代码走一遍

这段只用 Python 标准库，不下载模型、不访问网络。本站已逐课运行并核对下方结果；核对的是本例的数值结果，不代表框架训练或 GPU 性能已通过验证。

rows = [[1, 2, 3], [4, 5, 6]]
bias = [10, 20, 30]
assert all(len(row) == len(bias) for row in rows)
result = [[value + bias[j] for j, value in enumerate(row)]
          for row in rows]
print((len(result), len(result[0])))
print(result)

这组输入的运行结果：

(2, 3)
[[11, 22, 33], [14, 25, 36]]
  1. 输入有两行，每行 3 项；bias 的 3 项按列对应。
  2. 第一行：1+10=11，2+20=22，3+30=33。
  3. 第二行：4+10=14，5+20=25，6+30=36。
  4. 结果仍是 2 行 3 列。这里只用标准库手工演示此例，没有实现通用张量广播。

对照 PyTorch 的写法

框架对照代码：2026 年 10 月 30 日已在独立 CPU 环境（Python 3.12.14、PyTorch 2.15.0+cpu）运行，并核对本例的数值与运行边界。自行运行仍需安装 PyTorch；网页不会自动安装依赖或下载模型。此结果不包含真实微调或 GPU 性能验证。

import torch
x = torch.tensor([[1, 2, 3], [4, 5, 6]])
bias = torch.tensor([10, 20, 30])
assert x.shape == (2, 3)
print(x + bias)  # 广播后仍为 (2, 3)
