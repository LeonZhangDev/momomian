运行环境：先确认用了哪个 Python

约 10 分钟 · 无需模型账号

函数列表与字典判断与循环异常JSON 与 HTTP一次接口调用对象与 self运行环境
选学：读懂迭代、异步与中途停止迭代与取消：看懂分块到达的结果

本课学完，你能做什么

  • 区分解释器、工作目录和模块位置
  • 按报错找到应核对的环境条件
  • 知道 .env 文件需要明确的加载方式

同一份菜谱在不同厨房执行，器具和原料可能不同。解释器像厨房，依赖像器具，工作目录像当前操作台。菜谱写着杯子，并不表示每个厨房都已经摆好杯子。

安装依赖与运行程序要使用同一解释器

终端里的 python、编辑器选择的 Python、虚拟环境里的 Python 可能不是同一个程序。模块未找到时，先核对当前解释器和依赖所在环境。使用“所选解释器 -m pip”能让安装动作指向该解释器。

本课用虚构路径演示诊断，不读取本机环境，也不自动安装包。

相对路径从工作目录出发

打开 scripts/demo.py 不表示工作目录已经切到 scripts。读取 data.json 时，程序通常按当前工作目录解析相对路径；若需要相对于脚本定位，应明确按脚本位置构造路径。

文件存在于项目里，但程序从另一个目录启动，仍可能报文件未找到。

.env 是配置文本，不会被所有程序自动读取

环境变量由进程环境或明确的加载器提供。仅新建 .env 文件，不保证 Python、SDK 或浏览器自动读到它。先核对项目约定的加载位置和启动器；诊断只需说明缺哪个字段，不应打印密钥。

本课只比较“已加载/未加载”布尔状态，不读取或展示任何真实配置。

顺着代码走一遍

runtime = {"python": "project-venv", "cwd": "project", "env_loaded": False}
installed = {"system-python": {"demo_sdk"}, "project-venv": set()}
print("module_available:", "demo_sdk" in installed[runtime["python"]])
print("config_loaded:", runtime["env_loaded"])
print("relative_path:", runtime["cwd"] + "/data.json")

预期内容如下。字典的显示可能使用单引号；判断时看字段和值。

module_available: False
config_loaded: False
relative_path: project/data.json
  1. 固定样例选择 project-venv 作为运行解释器。
  2. demo_sdk 仅登记在 system-python，因此当前环境检查为 False。
  3. .env 加载状态是 False，不能因为文件存在就当成配置已生效。
  4. 相对 data.json 在本例从 project 解析；这些是虚构环境标签。
