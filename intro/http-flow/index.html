课程 / 编程与接口 / 第 6 节

一次接口调用：从请求到业务结果

约 12 分钟 · 无需模型账号

函数列表与字典判断与循环异常JSON 与 HTTP一次接口调用对象与 self运行环境
选学：读懂迭代、异步与中途停止迭代与取消：看懂分块到达的结果

本课学完，你能做什么

  • 列出方法、路径、头和 JSON 正文
  • 先检查状态，再解析与校验返回
  • 识别 HTTP 成功与业务成功的区别

前台签收申请，只表示表格已被接收。是否有空位、是否成功预约、确认编号是什么，还要继续看处理结果。接口也需要按层读取。

客户端整理请求，服务端按协议返回

本课 fake_transport 是一个普通 Python 函数，模拟接口边界，不开端口、不访问网络。请求包含 method、path、headers 和 body，返回包含 status 与 JSON 正文。真实 HTTP 客户端还需要超时、连接和异常处理。

POST /appointments 表示按本课约定提交预约申请，Content-Type 说明正文按 JSON 编码。

检查传输与数据结构

先区分是否取得响应，再看状态码和正文。JSON 可解析之后，还需要核对字段类型及允许值。500、非 JSON 正文、缺少关键字段不应统一显示为“预约成功”。

本课的固定正文可解析，包含 ok=False 和 error=no_capacity。

业务状态决定给用户的反馈

本课约定 HTTP 200 可以携带业务拒绝，因此仍需读取 ok 与错误码。成功写操作还应提供可核对的编号。超时没有正文时，不能凭客户端等待结束就断定服务端未执行。

“没有空位，请换时间”是可恢复的业务拒绝；它不同于“编号 A-01，已确认”。

顺着代码走一遍

import json

def fake_transport(request):
    payload = json.loads(request["body"])
    assert request["method"] == "POST"
    assert payload["people"] == 2
    return {"status": 200, "body": json.dumps({"ok": False, "error": "no_capacity"})}

request = {"method": "POST", "path": "/appointments",
           "headers": {"Content-Type": "application/json"},
           "body": json.dumps({"date": "2030-05-01", "people": 2})}
response = fake_transport(request)
result = json.loads(response["body"])
print(response["status"])
print(result["ok"])
print("请换时间" if result["error"] == "no_capacity" else "检查结果")

预期内容如下。字典的显示可能使用单引号；判断时看字段和值。

200
False
请换时间
  1. 将预约日期和人数编码为 JSON 正文，与方法、路径和头一起组成请求。
  2. fake_transport 解析请求，按固定样例返回 HTTP 200。
  3. 客户端解析正文，取得 ok=False 和 no_capacity。
  4. 用户看到“请换时间”，不会因 HTTP 200 就收到成功预约的提示。
