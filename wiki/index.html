Agent 百科

遇到不懂的词，就在这里查。

先弄清概念，需要评估系统时再查指标。

先看这六个概念；也可以直接搜索全部 32 个条目。

搜索结果

    从这六个概念开始

    • Agent 智能体围绕目标，根据当前状态和工具返回选择下一步，并有明确停止条件的程序。→
    • ReAct 循环把决定动作、执行工具和观察结果连成循环，新结果影响下一步。→
    • 工具调用模型或规则提出工具名与参数，由应用校验并实际执行，再返回可核对的结果。→
    • RAG 检索增强生成先从资料里检索相关片段，再让回答使用这些证据。→
    • 上下文本次请求实际提供给模型的信息，包括规则、消息、证据和工具回执。→
    • 短期与长期记忆由应用决定哪些信息保存、何时检索、怎样更新，以供当前或未来任务使用。→
    • LangGraph 状态图用状态、节点和边组织执行过程；节点返回状态更新，边决定接下来走哪里。→
    • 检查点与中断恢复保存流程状态，在审批或故障后用同一执行身份继续。→
    • 幂等按约定重复执行同一业务操作时，最终效果不额外增加；常用服务端请求键实现去重和结果复用。→
    • MCP 工具接入协议为客户端与能力提供方约定交互方式，便于发现和调用工具等能力。→
    • Embedding 与相似检索把文本编码为向量，用某种距离或相似度寻找候选资料。→
    • 重排 Rerank对已召回的候选再作更细的相关性判断，调整先后顺序。→

    你想检查哪一部分？

    找得准、找得全吗？

    先区分漏掉关键资料、混入无关资料和排序靠后。

    • 查准率 Precision@k拿回来的资料，有多少真正相关？→
    • 召回率 Recall@k应该找到的关键资料，还漏了多少？→
    • 命中率 Hit@k有多少个问题，至少找到了一个相关结果？→
    • 检索 F1@k查准与查全能否兼顾？→
    • 首个相关结果 MRR@k用户要往下翻多久，才能看到第一个有用结果？→
    • 分级排序 nDCG@k最有用的资料，是否排在最前面？→

    回答可信吗？

    检查回答与证据、事实和引用之间的关系。

    • 证据忠实度回答说出的事实，资料真的支持吗？→
    • 事实正确性回答中的事实，本身对不对？→
    • 引用支持率标上的引用，真的支持它旁边那句话吗？→

    工具和任务办成了吗？

    把中间调用与最终目标分开看。

    • 任务成功率用户交代的事，最后办成了多少？→
    • 工具调用成功率每一次工具尝试，有多少拿到了可确认的成功结果？→
    • 工具选择准确率到了要决策的时候，选对工具了吗？→
    • 参数有效率工具名选对后，传进去的参数能用吗？→
    • 故障恢复成功率已经遇到故障的任务，有多少能安全继续？→

    等多久、花多少？

    一起核对速度、用量、成功率和成本。

    • 端到端延迟与 P50/P95大多数人等多久，比较倒霉的人又等多久？→
    • 首个输出延迟 TTFT点击发送后，多久能看到第一段有效内容？→
    • 吞吐量同一段时间，系统一共处理了多少？→
    • Token 用量一次任务实际读入和生成了多少？→
    • 每次任务成本用户每发起一件事，平均花多少钱？→
    • 每次成功任务成本为了真正办成一件事，总共付出了多少？→

    怎样比较两组指标？

    先对齐任务、数据、统计单位、分母和实现版本，再看样本数与错例。宏平均先逐组计算再平均，微平均先合计计数再计算；它们可能不同。没有对所有系统都适用的“80% 就算好”，也不要让一个总分代替具体问题。
