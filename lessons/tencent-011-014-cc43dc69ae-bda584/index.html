固定一种矩阵方向，再检查乘法

本例约定列向量 x，底座 W 形状 [d_out,d_in]，A 为 [r,d_in]，B 为 [d_out,r]，所以 ΔW=sBA 能加到 W。不同框架可能使用转置存储，不能只按变量名字猜方向。这里 d_in=d_out=2、r=1、s=1。

底座冻结不等于没有训练

LoRA 训练时底座参数不更新，选择的 A、B 等适配器参数参与更新。常见初始化可令 B 为零，使初始增量为零；这不表示 A、B 都应永远为零。本例人为指定一次更新后的 B，用来观察前向差异，不模拟优化器求梯度。

保存适配器要保留底座身份

适配器不是完整模型。重载要核对底座版本、目标层、rank、缩放、权重布局、tokenizer 及相关配置。合并适配器时需防止重复加上同一个增量；训练参数减少也不自动保证所有显存和推理成本按相同比例减少。

把输入代进去，走一遍

以下是本站固定教学样例，用来观察规则，不是线上服务的测量结果。

固定玩具 W=[[1,0],[0,1]]，x=[2,3]，A=[[1,-1]]，初始 B=[[0],[0]]，一次人为指定的更新后 B=[[0.2],[-0.1]]，s=1。

步骤当前内容或状态为什么这样变化
底座输出Wx=[2,3]W 是单位矩阵，输出与输入相同。
低秩中间量Ax=[2-3]=[-1]由二维输入压到 rank=1 的中间维度。
增量输出B(Ax)=[-0.2,0.1]将 rank=1 的中间结果映射回两维输出。
适配后输出Wx+B(Ax)=[1.8,3.1]原 W 保持不变，只增加适配器分支贡献。
保存和恢复核对保存 A、B、s 与 base_revision；重载同底座后输出仍应为 [1.8,3.1]本例在内存中复制配置并重算，不下载或写入真实模型。

最后得到：玩具前向输出从 [2,3] 变成 [1.8,3.1]。这里 W 的 4 个参数冻结，A、B 共 4 个参数；小维度下并没有参数节省，r 必须结合实际层宽判断。

查看完整 Python 推导与预期输出

标准库教学程序。固定输入的输出会随课程构建核对；不访问模型或外部服务。

import json
w = [[1,0],[0,1]]
x = [2,3]
a = [[1,-1]]
b = [[0.2],[-0.1]]
base = [sum(v*t for v,t in zip(row,x)) for row in w]
ax = sum(v*t for v,t in zip(a[0],x))
delta = [row[0]*ax for row in b]
print(base)
print([round(v+d,6) for v,d in zip(base,delta)])
saved = json.dumps({"a": a,"b": b,"scale":1,"base_revision":"toy-v1"})
loaded = json.loads(saved)
restored_ax = sum(v*t for v,t in zip(loaded["a"][0],x))
restored = [round(v+loaded["scale"]*row[0]*restored_ax,6) for v,row in zip(base,loaded["b"])]
assert restored == [1.8,3.1]
print(loaded["base_revision"])
print([round(v+2*d,6) for v,d in zip(base,delta)])

预期输出：

[2, 3]
[1.8, 3.1]
toy-v1
[1.6, 3.2]

如果这一步出错呢？

触发条件：把适配器当作完整底座，或在已合并的 W 上再次启用同一增量。

重复加增量会得到 [1.6,3.2]，不是正确的 [1.8,3.1]；换底座后即使维度相同，也不能假定行为一致。

恢复方法：记录底座修订与合并状态，用固定输入比较加载前后输出；保留未合并版本，避免无依据覆盖。

查看解释与参考资料

Llama-2-7B 按 32 层、四个 4096×4096 投影和 r=16，LoRA 参数应约 16,777,216，注释不是此配置结果。

from peft import LoraConfig, get_peft_model, TaskType
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
import torch

model_name = "meta-llama/Llama-2-7b-hf"
model = AutoModelForCausalLM.from_pretrained(
    model_name, torch_dtype=torch.float16, device_map="auto",
    load_in_4bit=True, # 4-bit 量化加载（QLoRA），进一步省显存
)

# 配置 LoRA
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM, r=16, lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# -> trainable: 4,194,304 || all: 6,742,609,920 || 0.0622%

更正：LoRA 减少可训练状态，可保存多个适配器；显存、速度和文件大小按模型、rank、模块与实际训练负载测量。

查看解释与参考资料

没有基线、序列和精度配置，不能作为通用保证；适配器大小也随模块和 rank 变化。

LoRA 优势：只训练不到 1% 的参数，显存降低 60-70%，速度快 2-3 倍，权重文件仅几 MB，可为同一基础模型保存多个 LoRA 适配器用于不同任务。
