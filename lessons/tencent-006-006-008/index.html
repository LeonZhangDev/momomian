卡住时，先补哪一小节？
  • 字典与字段访问

先决定值不值得记，再决定写到哪里

一句话进入本次上下文不等于长期保存。可以先抽取候选，再按产品约定判断是否是稳定偏好、是否有明确来源、是否允许保存。本文教学规则要求用户明确确认，才写入饮品偏好；这是本例的产品规则，不是所有框架自动提供的功能。

同一事实用稳定键更新，不不断追加矛盾记录

为虚构用户u1保存 fact_key=drink，版本v1为咖啡。用户更正为茶后，应产生v2并让旧版本失效；检索时过滤有效版本。向量相似度只能找到相近记录，不能自行决定哪个版本是用户最终决定。还要保留来源、时间、范围与更正关系。

用户隔离、线程范围和磁盘持久化分开

线程历史只属于该次会话；长期事实可以按用户命名空间跨线程读取。命名空间本身不是授权检查：服务端仍要确认请求者有权访问u1。内存字典或InMemoryStore在进程退出后通常不保留数据；跨进程恢复需要真实持久后端与保存规则。删除还要让索引、缓存及后续注入失效，并按实际保留政策处理历史副本。

把输入代进去，走一遍

以下是本站固定教学样例，用来观察规则，不是线上服务的测量结果。

教学规则：确认后保存。u1在thread-a说“我偏好咖啡”，确认写v1；随后更正“以后改喝茶”，确认写v2。u1在thread-b询问偏好；u2也发起查询。最后u1要求删除饮品偏好。

步骤当前内容或状态为什么这样变化
1 · 候选candidate={user:u1,key:drink,value:咖啡}；未入库当前看见这句话不等于获得保存许可。
2 · 确认写入(u1,drink,v1)=咖啡，active=true记录确认与来源，不按裸文本作为全局公共事实。
3 · 更正v1 inactive；v2=茶 active同一稳定事实键的新有效版本替代旧值。
4 · 跨线程读取u1/thread-b→茶；u2→无此事实读取范围按已授权用户限制，线程变化不自动获得别人记忆。
5 · 删除drink不再参与检索与上下文注入同时处理主存、索引与缓存；若有依法或按约定保留的历史副本，应如实说明范围。

最后得到：u1更正后使用茶，u2不能读到u1的事实。删除后不再把该偏好提供给模型。下方标准库代码只演示内存键值更新与隔离，不证明磁盘持久化、权限系统或完整删除已实现。

如果这一步出错呢？

触发条件：把新偏好直接追加到全局向量库，只按相似度读取，不过滤用户与有效版本。

咖啡与茶同时命中 → 旧值相似度更高被采用；u2的查询还可能读到u1；仅删主表但缓存保留时，下一轮仍注入旧偏好。

恢复方法：查询前做服务端身份与范围检查，读取有效事实版本；更正更新索引与缓存。删除后验证检索与下一次上下文不再出现该值，持久化恢复和备份清理由各后端的明确规则另验。

长期记忆

概述

LangChain 智能体使用 LangGraph 持久化 来实现长期记忆。这是一个更高级的主题，需要了解 LangGraph 才能使用。

记忆存储

LangGraph 将长期记忆作为 JSON 文档存储在 存储 中。

每个记忆都组织在一个自定义的namespace（类似于文件夹）和一个唯一的key（类似于文件名）下。命名空间通常包含用户或组织 ID 或其他标签，以便于组织信息。

这种结构支持记忆的层次化组织。然后通过内容过滤器支持跨命名空间的搜索。

更正：return [[1.0, 2.0] for _ in texts] # 仅作每条文本对应二维向量的占位演示；生产中须替换真实embedding实现。

查看解释与参考资料

该写法把所有文本拼成一个向量，批量输入时既少了行数又改变维度。

from langgraph.store.memory import InMemoryStore

def embed(texts: list[str]) -> list[list[float]]:
# Replace with an actual embedding function or LangChain embeddings object
return [[1.0, 2.0] * len(texts)]

# InMemoryStore saves data to an in-memory dictionary. Use a DB-backed store in production use.
store = InMemoryStore(index={"embed": embed, "dims": 2})
user_id = "my-user"
application_context = "chitchat"
namespace = (user_id, application_context)
store.put(
namespace,
"a-memory",
{
"rules": [
"User likes short, direct language",
"User only speaks English & python",
],
"my-key": "my-value",
},
)
# get the "memory" by ID
item = store.get(namespace, "a-memory")
# search for "memories" within this namespace, filtering on content equivalence, sorted by vector similarity
items = store.search(
namespace, filter={"my-key": "my-value"}, query="language preferences"
)

在工具中读取长期记忆

一个智能体可以用来查找用户信息的工具

from dataclasses import dataclass

from langchain_core.runnables import RunnableConfig
from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime
from langgraph.store.memory import InMemoryStore

@dataclass
class Context:
user_id: str

# InMemoryStore saves data to an in-memory dictionary. Use a DB-backed store in production.
store = InMemoryStore()

# Write sample data to the store using the put method
store.put(
("users",), # Namespace to group related data together (users namespace for user data)
"user_123", # Key within the namespace (user ID as key)
{
"name": "John Smith",
"language": "English",
} # Data to store for the given user
)

@tool
def get_user_info(runtime: ToolRuntime[Context]) -> str:
"""Look up user info."""
# Access the store - same as that provided to `create_agent`
store = runtime.store
user_id = runtime.context.user_id
# Retrieve data from store - returns StoreValue object with value and metadata
user_info = store.get(("users",), user_id)
return str(user_info.value) if user_info else "Unknown user"

agent = create_agent(
model="claude-sonnet-4-5-20250929",
tools=[get_user_info],
# Pass store to agent - enables agent to access store when running tools
store=store,
context_schema=Context
)

# Run the agent
agent.invoke(
{"messages": [{"role": "user", "content": "look up user information"}]},
context=Context(user_id="user_123")
)

从工具写入长期记忆

更新用户信息的工具示例

from dataclasses import dataclass
from typing_extensions import TypedDict

from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime
from langgraph.store.memory import InMemoryStore

# InMemoryStore saves data to an in-memory dictionary. Use a DB-backed store in production.
store = InMemoryStore()

@dataclass
class Context:
user_id: str

# TypedDict defines the structure of user information for the LLM
class UserInfo(TypedDict):
name: str

# Tool that allows agent to update user information (useful for chat applications)
@tool
def save_user_info(user_info: UserInfo, runtime: ToolRuntime[Context]) -> str:
"""Save user info."""
# Access the store - same as that provided to `create_agent`
store = runtime.store
user_id = runtime.context.user_id
# Store data in the store (namespace, key, data)
store.put(("users",), user_id, user_info)
return "Successfully saved user info."

agent = create_agent(
model="claude-sonnet-4-5-20250929",
tools=[save_user_info],
store=store,
context_schema=Context
)

# Run the agent
agent.invoke(
{"messages": [{"role": "user", "content": "My name is John Smith"}]},
# user_id passed in context to identify whose information is being updated
context=Context(user_id="user_123")
)

# You can access the store directly to get the value
store.get(("users",), "user_123").value
