本课机制与检查方向

先用这个入门例子理解流程，再看下方完整讲解。

本课讨论自回归慢，主要的串行约束是什么？ 结论：后续token依赖先前已生成内容。 理由：训练已知目标序列时可并行计算位置，生成时未来内容未定，通常逐步扩展，KVCache能减少重复计算，但不消除这种序列依赖。 配套示例：要生成第三个token，需基于已经产生的前两个token继续推断。 本课对越来越长的对话记忆提出什么处理？ 结论：总结并提取关键事实，控制进入当前窗口的内容。 理由：上下文容量有限，摘要用于保留关键事实同时减少长度，摘要也需检查是否遗漏重要约束，不能把压缩理解为任意删除或保证完全无损。 配套示例：保留用户确认的日期和偏好，压缩重复寒暄，再继续当前预约对话。

Prompt Chaining是具有范式和通用性的，它是一种线性执行的设计模式，适用于将复杂任务拆解成多个连续的LLM调用，每一步输出作为下一步输入，不依赖于多个Agent协作，通过单一代理在多个阶段逐步处理任务，常适用于多轮推理，任务分解的系统。

7.照你所说，Transformer是一个比较并行的结构，但是大家拿他来做自回归，它完全是一个串行的，这个会使得他利用率有很大问题，你能谈一下你的理解吗？

更正：普通自回归解码跨 token 有顺序依赖；单步计算和多请求批处理仍可并行，推测解码也可能一次验证多个候选 token。

查看解释与参考资料

跨 token 生成存在顺序依赖，但单步内部、批处理和推测解码仍可并行。

（先承认这一问题）对的，Transformer的优势在于编码阶段可以高度并行，可以通过自注意力机制同时处理整个序列的所有位置，使得训练时效率，GPU/TPU利用率很高。 但是推理阶段，如果采用自回归生成，每次只能预测一个token，再把它拼接，才能预测下一个token，因此无法并行，延迟比较严重。

（强调必要性）但是由于语言的自然属性，它是强序列相关的，未来的token分布依赖于过去的token，所以非自回归训练的生成质量往往不如自回归，容易出现流畅性和一致性问题。所以常见的大语言模型还是使用自回归。

(解决思路)但是我们仍然可以通过比如KV缓存的方式减少重复计算，提升推理速度，Speculative Decoding的方式来减少串行步骤 从而做出一些优化。

8.1 如何让这个对话系统可以保持记忆功能呢？

5 Agent的记忆功能是如何实现的？

8.2 那这个记忆会越来越长，要怎么办呢？

我们会维护这个上下文窗口，当超过指定窗口的时候，会进行总结，提取关键信息和要点，因此这个记忆不会无限制增加的。

8.3你如果每次都会带上之前的上下文，那他的时间复杂度会不会成倍增长？

更正：标准全注意力的序列两两交互开销随长度约呈 O(n²)；整模型时延、KV 缓存解码和 API 费用需分别测量，不能直接认定输入翻倍就全部成本四倍。

查看解释与参考资料

标准全注意力矩阵计算对序列长为二次，但整模型、缓存解码和计费并不都精确四倍。

理论上来说，基于transformer的架构，计算复杂度和上下文关系成二次关系O(n^2), 意味着上下文翻倍，成本计算会增加4倍。

但是实际上，我们可以使用一些比如稀疏注意力，分块处理，缓存机制以及GPU/TPU的并行计算的能力来缓解这个性能问题。

    反思
    对已有结果进行检查和修正的过程。自我检查不是独立验证，仍需外部标准或测试。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Agent
    围绕目标读取状态、选择动作、观察结果并判断是否继续的程序。行动权限与停止条件需要明确设计。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    LLM
    通过训练学习语言规律、根据上下文生成内容的模型；输出可用性和事实正确性仍需要检查。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Token
    分词器处理文本得到的单位。它不固定等于一个汉字、一个单词或一个字符。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Prompt
    向模型提供任务、上下文、约束和输出要求的输入内容；提示本身不能代替程序权限校验。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    上下文窗口
    单次模型处理所能容纳的信息范围。放进窗口的信息与存到外部数据库的信息不同。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    RAG
    先从资料中取回相关内容，再将检索结果作为生成回答的上下文；检索与回答依据应分别检查。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Embedding
    将文本等对象表示为数值向量的方法，用于比较或检索；向量相近不自动证明事实正确。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Chunk
    为索引和检索划分的内容片段。片段应保留必要上下文和来源，边界需要结合资料结构选择。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    记忆
    为后续使用保留信息的机制。近期会话、跨会话偏好与操作审计的范围和用途应分开。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    HTTP
    客户端与服务端交换请求和响应的协议；方法、状态码、响应体和业务结果分别提供信息。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    缓存
    保存可复用结果以减少重复工作。命中率、键的范围、失效与更新策略会影响正确性。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Transformer
    利用注意力等结构处理序列表示的一类模型架构。具体结构、输入与训练目标随模型而异。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    注意力
    根据输入表示计算并汇总相关信息的机制。权重不是对模型所有行为的完整因果解释。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Prompt Chaining
    Prompt Chaining是具有范式和通用性的，它是一种线性执行的设计模式，适用于将复杂任务拆解成多个连续的LLM调用，每一步输出作为下一步输入，不依赖于多个Agent协作，通过单一代理在多个阶段逐步处理任务，常适用于多轮推理，任务分解的系统。原文解释节选；未独立核验技术结论。 回看本课上下文
