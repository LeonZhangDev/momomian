第一关：文本能否被解析

JSON 语法只约定文本怎样表达对象、数组、字符串和数字。单引号、缺逗号可能在这一关失败；能解析仅说明文本结构成立。不要用执行代码的方式解析模型输出，应使用 JSON 解析器。

第二关：字段是否符合约定

本例要求 items 是整数列表、total 是整数，且不接受额外字段。Schema 或类型校验器适合表达这些字段规则；Python bool 是 int 的子类，因此手写整数判断要明确是否排除布尔值。本例规定排除。具体结构化能力和错误处理依赖所用模型、接口及版本。

第三关：字段之间是否一致

业务还要求 total 等于 items 的和。{"items":[30,20],"total":70} 可以通过 JSON 与字段类型检查，却违反30+20=50的关系。需要显式业务校验。即使结构和关系都通过，金额是否来自真实证据仍需核对；结构化输出不能替代事实验证。

虚构明细 items=[30,20]。候选A={"items":[30,20],"total":70}；候选B={"items":[30,20],"total":50}。金额单位只用于本页教学。

步骤当前内容或状态为什么这样变化
1 · 解析 AJSON 可解析双引号、列表和数字都合法。
2 · 检查字段 Aitems 为整数列表；total 为整数；无额外字段这里字段检查通过，不代表金额关系成立。
3 · 检查关系 Asum(items)=50≠70；拒绝进入后续计算记录 expected_total=50、actual_total=70，指出矛盾字段。
4 · 检查 Bsum(items)=50=total；三层检查通过这只证明给定对象内部一致；真实明细来源仍是另一项核对。

最后得到：A 应报告 total 与明细之和不一致；B 可以进入本题后续步骤。若下游要支付或写账，还需要身份、证据、授权与执行回执。

查看完整 Python 推导与预期输出

标准库教学程序。固定输入的输出会随课程构建核对；不访问模型或外部服务。

import json

for raw in ['{"items":[30,20],"total":70}', '{"items":[30,20],"total":50}']:
    row = json.loads(raw)
    schema_ok = set(row) == {"items", "total"} and isinstance(row["items"], list) and all(type(x) is int for x in row["items"]) and type(row["total"]) is int
    business_ok = schema_ok and sum(row["items"]) == row["total"]
    print(schema_ok, business_ok)

如果这一步出错呢？

触发条件：把“指定了 JSON 输出”或“Schema 校验通过”当成所有业务规则都满足。

A 的 total=70 类型正确 → 下游直接入账 → 多算20。虽然接口无报错，业务结果已经错了。

恢复方法：按层返回可定位的错误；如果明细可靠，可在程序中重新计算派生总额，并标记该处理。若需要模型修正，传回矛盾字段并限定次数；来源矛盾时停止并核对原资料，不循环猜数。

精准控制输出格式

你不只是想要一个好答案，更想要以特定方式呈现的好答案——比如 JSON、表格、Markdown 报告，或者干脆的一句话。

方法一：直接描述你想要的格式

分析以下产品评论的情感，以 JSON 格式输出，包含以下字段：
- sentiment：值为 "positive"、"negative" 或 "neutral"
- score：0 到 10 的整数，代表情感强度
- key_phrases：最多 3 个关键短语组成的列表
- summary：不超过 20 字的中文摘要

只输出 JSON，不要有任何额外的解释文字。

<review>
这款耳机的降噪效果出乎意料地好，戴上就像进入了另一个世界。
但续航只有 18 小时有点让人失望，价格也略贵……
</review>
期望输出：

{
  "sentiment": "positive",
  "score": 7,
  "key_phrases": ["降噪效果好", "续航偏短", "价格略贵"],
  "summary": "降噪优秀但续航和价格略有不足"
}
