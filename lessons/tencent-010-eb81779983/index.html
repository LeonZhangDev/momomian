每个块都要知道自己属于哪份原文

doc_id标识逻辑文档，version区分内容版本，chunk_id区分该版本的块，source_position定位页码或段落。embedding_version标明向量所用模型与预处理配置，避免把不兼容向量随意比较。内容相同的两个块也可能有不同的文档权限，不能只按文本去重后丢掉范围。

先准备新版本，再切换有效版本

更新时可先暂存v2所有块、向量与必要元数据，检查完整后再把active_version从v1切到v2。这样索引写入中途失败时，读者仍看到完整v1，不会一半新规一半旧规。具体原子切换方式取决于所用数据库和索引，本文演示这个约定，不声称所有系统自动支持。

下线与删除要覆盖真正的查询路径

查询先核对用户权限、文档有效性与目标版本，再做排序。删除逻辑文档后，旧向量、缓存答案和引用解析都不能继续无提示地提供它。保留审计历史或备份时，应按实际政策说明，不能把“查询不可见”说成“所有介质永久消失”。

2.3 文档分块（Chunking）

这是最关键的一步！为什么要分块？

想象一下： 你有一本500页的《红楼梦》，如果有人问"林黛玉是谁"，你不可能把整本书都递给他看吧？你会翻到介绍林黛玉的那几页。

分块就是这个道理：把大文档切成小段，每段包含一个相对完整的语义单元。

常见的分块策略：

  1. 固定大小分块（最简单，但可能切断语义）

离线核验：离线实测（Python 3.12.14，langgraph 1.2.17，langchain-core 1.7.0，typing-extensions 4.16.0，pydantic 2.14.1）：原片段补缺失上下文或判定桩后通过，不计独立运行。补入明确的合成文本或列表，核对原块结果；不调用外部服务，不计独立原工程运行。。仅覆盖所列输入与断言。

#每300个字符一块
chunk_size = 300
chunks = [text[i:i+chunk_size] for i in range(0, len(text), chunk_size)]
  1. 句子分块（按自然语言边界）
#按句号、问号、感叹号分割
import nltk
sentences = nltk.sent_tokenize(text)
段落分块（保留逻辑结构）
#按换行符或段落标记分割
chunks = text.split('\n\n')
滑动窗口分块（带重叠，避免信息丢失）

chunk_size = 300
overlap = 50 # 重叠50字符
chunks = []
for i in range(0, len(text), chunk_size - overlap):
    chunks.append(text[i:i+chunk_size])

分块的关键参数：

  • 块大小（Chunk Size）
  • 太小 → 语义不完整；太大 → 检索不精准

  • 更正：使用选定模型的分词器实测中文资料的token数；注明chunk_size的计量单位，并在固定业务集上调参。

    查看解释与参考资料

    token与汉字不是固定比例，200–500只是候选块长，字符切片代码也没有执行token预算。

    推荐：200-500 tokens（约150-400个汉字）
  • 重叠（Overlap）
  • 避免关键信息被切断
  • 推荐：10-20% 的块大小

2.4 向量化（Embedding）

分块后的文本还是人类语言，机器不懂。我们需要把它转换成向量（一串数字）。

什么是Embedding？

把文字转换成数字向量，相似的文字会得到相似的向量。

#使用OpenAI的Embedding模型
from openai import OpenAI
client = OpenAI()

text = "阿司匹林是一种解热镇痛药"
response = client.embeddings.create(
    model="text-embedding-3-small",
 input=text
)
vector = response.data[0].embedding
print(f"向量维度: {len(vector)}") # 输出: 1536
print(f"前5个值: {vector[:5]}") # 输出: [0.023, -0.014, 0.089, ...]

为什么需要向量化？

想象你在找"感冒药"，但文档里写的是"抗感冒药物"、"治疗感冒的药品"等各种说法。如果只靠关键词匹配，就找不到了。

但是！如果用向量化：

"感冒药" → [0.1, 0.3, 0.5, ...]
"抗感冒药物" → [0.12, 0.29, 0.51, ...]  # 向量很接近！
"汽车" → [0.8, 0.1, 0.2, ...]  # 向量差很远

向量之间可以计算相似度（余弦相似度），数值越接近1越相似：

2.5 存储到向量数据库

最后，把这些向量存起来，用专门的向量数据库（Vector Database）。

为什么不用普通数据库？

普通数据库（MySQL、MongoDB）擅长精确查询："找ID=123的记录"。但向量搜索是相似性查询："找和[0.1, 0.3, 0.5]最相似的10个向量"。

向量数据库用了特殊的索引算法（如HNSW、IVF），能在百万、千万级向量中毫秒级找到最相似的。
