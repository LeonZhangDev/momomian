一条评估记录要能解释失败在哪里

资料助手给错答案，可能是没找到资料、找对却说错，或答对但写工具失败。只留一个“成功/失败”分数很难定位。下面同时记录相关文档集合、取回集合、受支持主张数、工具合法性、业务完成、耗时和费用。全部数字为固定教学样本。

先算一行，再汇总

Q1 标准相关文档有 a、b，取回 a、x，所以命中1个：Precision=1/2，Recall=1/2。回答有2个主张、仅1个被证据支持，支持率=1/2。工具有效但任务仍失败，因为回答包含不受支持的结论；不同层不能互相替代。

聚合方式也是指标的一部分

这里检索采用微平均：先累加命中和分母，再相除；不是把每行比例直接平均。主张支持率同样先合计主张。工具合法率只统计确实需要工具的5条，业务成功率统计全部6条。费用和延迟包含失败，避免删除慢失败后伪造改善。

    retrieved_set = set(retrieved_docs)
    relevant_set = set(relevant_docs)
    correct = retrieved_set.intersection(relevant_set)

指标2：准确率（Precision）

通俗解释：检索到的文档中，有多少是真正相关的？

准确率 = 检索到的正确文档数 / 检索到的总文档数
      = 2 / 3
      = 0.67 (67%)

指标3：MRR（Mean Reciprocal Rank）

通俗解释：第一个正确答案排在第几位？

def calculate_mrr(retrieved_docs, relevant_docs):
    """返回单个查询的倒数排名RR；多个查询的RR取均值才是MRR。"""
    for i, doc in enumerate(retrieved_docs, 1):
        if doc in relevant_docs:
            return 1.0 / i
    return 0.0
retrieved = ['doc5', 'doc7', 'doc1']
relevant = ['doc1', 'doc2']

    计算召回率

    Args:
        retrieved_docs: 系统检索到的文档ID列表
        relevant_docs: 真实相关的文档ID列表
    """
    retrieved_set = set(retrieved_docs)
    relevant_set = set(relevant_docs)

 # 检索到的正确文档
    correct = retrieved_set.intersection(relevant_set)

    recall = len(correct) / len(relevant_set) if relevant_set else 0

 return recall
