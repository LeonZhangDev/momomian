知识库更新：同一份文档怎样换版而不混版

  • 区分文档ID、版本、块ID、原文位置和嵌入版本
  • 追踪更新成功与更新失败时的可见状态
  • 删除后核对主存、索引与引用缓存

本单元的 3 篇材料共用这组串讲、小测和新卡。切换资料页不会产生重复的题目记录。

卡住时，先补哪一小节？
  • 稳定键与有效版本

每个块都要知道自己属于哪份原文

doc_id标识逻辑文档，version区分内容版本，chunk_id区分该版本的块，source_position定位页码或段落。embedding_version标明向量所用模型与预处理配置，避免把不兼容向量随意比较。内容相同的两个块也可能有不同的文档权限，不能只按文本去重后丢掉范围。

先准备新版本，再切换有效版本

更新时可先暂存v2所有块、向量与必要元数据，检查完整后再把active_version从v1切到v2。这样索引写入中途失败时，读者仍看到完整v1，不会一半新规一半旧规。具体原子切换方式取决于所用数据库和索引，本文演示这个约定，不声称所有系统自动支持。

下线与删除要覆盖真正的查询路径

查询先核对用户权限、文档有效性与目标版本，再做排序。删除逻辑文档后，旧向量、缓存答案和引用解析都不能继续无提示地提供它。保留审计历史或备份时，应按实际政策说明，不能把“查询不可见”说成“所有介质永久消失”。

以下是本站固定教学样例，用来观察规则，不是线上服务的测量结果。

虚构退款文档doc=refund-standard。v1/2025内容“期限14天”；v2/2026内容“期限7天，已使用服务例外”。v2拆成c1=期限、c2=例外，位置为第2段/第3段，embedding_version=toy-embed-v1。初始active_version=v1。

步骤当前内容或状态为什么这样变化
1 · 初始读取active=v1；查询只能引用v1的14天引用包含版本，不把旧内容标成2026版。
2 · 暂存新块staging={v2:c1,c2}；active仍为v1两个块完成前不对外混用。
3 · 检查完整2/2块元数据、位置与嵌入配置匹配若第二块写入失败，停在暂存，不切换有效指针。
4 · 切换版本active=v2；v1不参与当前查询新查询同时看到7天和例外，避免跨版拼接。
5 · 引用与删除引用绑定doc/v2/c1/第2段；删除后当前检索不返回该doc缓存与引用解析也要核对版本有效性和删除状态。

最后得到：只有完整v2准备好后，当前答案才按7天及例外回答。写入中途失败继续用完整v1，并明确其版本；不把部分更新当作已发布。

如果这一步出错呢？

触发条件：直接覆盖部分块，或只按doc_id把v1和v2混排。

c1写成7天但c2仍是旧例外 → 得到从未存在过的组合规则；删除主文档后缓存仍返回旧答案。

恢复方法：暂存并校验整组新版本，再按存储约定切换有效版本；失败保留可恢复状态。查询与缓存使用文档身份、版本和权限，删除后验证各读取路径。

换个条件，自己判断

v2的c1写入成功、c2失败。此刻active应该是哪版？如果用户明确要2026规则而v2未准备好，应该怎样答？

先口述、画两行状态或改一个值即可。检查方法在提交小测后也可以回来核对。

想完后，对照检查方向

  • 不混入c1形成半个v2
  • 说明新版本暂不可用，不把旧版冒充2026版

class HierarchicalRAG:
 """分层RAG：先粗筛，再精筛"""

 def retrieve(self, query: str):
 # 第1层：快速粗筛（Top 100）
        coarse_results = self.fast_retriever.search(query, k=100)

 # 第2层：精细重排（Top 20）
        fine_results = self.reranker.rerank(query, coarse_results, k=20)

 # 第3层：LLM筛选（Top 5）
        final_results = self.llm_filter(query, fine_results, k=5)

 return final_results

🚀 技巧4：实时更新知识库

补充说明：常见 LangChain 向量库 add_texts 的第二个位置参数是元数据，并不是预计算向量。需按实际接口使用命名参数或专用向量写入方法，避免重复计算或类型错误。

补充说明：删除接口通常需要 ID 列表等明确参数；原文档还可能对应多个块。先验证新版本可写，再切换可见版本并处理旧块，失败时保留恢复路径。

class IncrementalRAG:
 """支持增量更新的RAG"""

 def add_document(self, new_doc: str):
 """添加新文档"""
 # 切分
        chunks = self.text_splitter.split_text(new_doc)

 # 向量化
        vectors = self.embeddings.embed_documents(chunks)

 # 增量添加到向量库（不需要重建整个库）
        self.vectorstore.add_texts(chunks, vectors)

 print(f"✅ 已添加 {len(chunks)} 个新文档块")

 def update_document(self, doc_id: str, new_content: str):
 """更新文档"""
 # 删除旧版本
        self.vectorstore.delete(doc_id)

 # 添加新版本
        self.add_document(new_content)
