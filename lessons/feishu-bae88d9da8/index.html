本课目标

  • 选择一项扩展作业，写出输入、事件位置、输出和最小验收条件。
  • 说明会话回退与代码快照的不同，并列出恢复时需处理的冲突和未跟踪文件。

本课机制与检查方向

先用这个入门例子理解流程，再看下方完整讲解。

本课开机欢迎语扩展应订阅哪个事件？ 结论：session_start。 理由：欢迎语应在会话启动时触发，工具返回或供应商请求前属于任务运行阶段，不能对应开机这一时机。 配套示例：假设每次启动显示随机 quote，可以在 session_start 回调设置欢迎内容。 本课作业提醒 Pi 默认回退节点后，工作区代码会怎样？ 结论：只回退对话，代码需额外快照机制才能恢复。 理由：会话节点与文件系统是两类状态，回退消息不等于恢复磁盘；要联动代码需记录节点对应的 Git 快照并处理恢复。 配套示例：假设对话退回改文件前，文件本身仍可能保留改动，需另行恢复快照。

知识点讲解

5.5 课后作业

通过这个小节，我是希望能带大家了解PI Agent的一个大概的思想和架构。如果你是想在这个基础上继续去扩展，深入学习，还是得靠大家。我总结了一些可以去做的扩展任务，包括让AI也总结出来了对应的参考代码和官方示例（可能不准）大家多包涵。

如果想在 Pi 基础上动手，可以按下面几个难度推进。下面每条都尽量附上了官方对应的示例扩展或文档，建议先读官方实现再动手——Pi 自带的示例很全，照着改往往比从零写更快。扩展 API 的全貌见 docs/extensions.md，所有示例扩展都在 examples/extensions/ 下。

入门

  • 加一个 web search 工具：用 registerTool 注册一个调用搜索 API 的工具。作者自己也提到过，这是他会装的一个常用扩展。参考最小自定义工具示例 examples/extensions/hello.ts；API 见 extensions/types.ts 的 registerTool 和 ToolDefinition。
  • 写一个开机欢迎语扩展：订阅 session_start，启动时随机显示一句 quote。参考 examples/extensions/custom-header.ts（演示 ctx.ui.setHeader）和 hello.ts。

中级

  • 权限确认弹窗扩展：挂 tool_call hook，检测危险 bash 命令，比如 rm -rf、git push -f，执行前弹窗确认，拒绝就 block。官方已有现成示例 permission-gate.ts；相关的还有 protected-paths.ts（拦截对 .env、.git/ 等路径的写入）和 confirm-destructive.ts（清空 / 切换 / fork 等危险会话操作前确认）。
  • 用 todo 工具替代内置 todo：Pi 内核没有内置 todo。官方示例 todo.ts 演示了一个完整的 todo 工具 + /todos 命令，带自定义渲染和状态持久化，可以直接参考。
  • 自定义主题 / 状态栏：让 Pi 生成一套终端配色主题。入口 getAllThemes / setTheme，参考 mac-system-theme.ts（跟随系统深浅色）、status-line.ts、custom-footer.ts。

进阶

  • 更正：早期版本可练习 MCP 桥接；当前版本应先阅读官方 MCP 文档，选择配置已有接入或在独立练习中实现协议适配。

    查看解释与参考资料

    这属于旧版功能状态。当前官方 Pi 已提供 MCP 接入及 registerMcpServer；先检查当前能力，再决定作业是配置现成接入还是自行写桥接层。

    Pi 官方 MCP Servers ↗

    MCP adapter：写扩展，把 MCP server 的工具桥接到 Pi 的工具系统。官方没有直接的 MCP 示例，但可以参考 dynamic-tools.ts（运行时动态注册工具）和 ssh.ts（把工具委派到外部进程）的写法。
  • 子代理：注册一个工具，工具内部再启动一个 Agent Core 实例处理子任务。官方有完整示例 examples/extensions/subagent/，演示带独立上下文窗口的子代理委派。
  • Plan 模式：用扩展实现"先出计划，确认后再执行"的工作流，Pi 默认没有这个模式。官方示例 examples/extensions/plan-mode/ 实现了 Claude Code 风格的 /plan（只读探索 + 步骤跟踪）。

更正：可参考示例理解节点与快照关联；实际使用要处理引用持久化、未跟踪文件、恢复确认和冲突，先用临时仓库验证。

git-checkpoint 示例的引用表在内存中，恢复使用 stash apply，可能冲突且不是覆盖所有文件的事务快照。不要直接把它当生产级撤销。

Pi git-checkpoint 官方示例 ↗

- 节点回退后文件也一起回退：如 1.2 所说，Pi 默认 fork / 回退只回退对话，不动工作区代码。这个作业就是把代码也接上：订阅 turn_start 时用 git stash create 给当前代码打一个快照并和会话节点关联，在 session_before_fork 时用 git stash apply 把代码还原到那个节点。官方有现成示例 [git-checkpoint.ts](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/git-checkpoint.ts)，几乎可以直接用；另见 [auto-commit-on-exit.ts](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/auto-commit-on-exit.ts)。

  • 用 RPC 模式接入你自己的 OpenClaw：Pi 的 Agent Core 可以脱离 TUI，被别的程序通过 RPC 当后端驱动（见 3.7 的三种运行模式）。这个作业是把你自己的前端 / 程序 OpenClaw 作为 RPC 客户端接进来，由它发消息、收事件，Pi 只当"无头大脑"。参考 RPC 协议文档 docs/rpc.md，以及扩展侧 UI 示例 rpc-demo.ts（搭配 examples/rpc-extension-ui.ts 一起看）。

挑战

  • 从零仿写一个极简 harness：照着 agent-loop.ts 的主干，用任意语言实现一遍 init context -> call LLM -> tool loop -> reply，再加上 JSONL 树状会话。这个练习最能帮助你吃透 Agent 的基本运行方式。
