查看解释与参考资料

适合学习可以由可读代码、测试与文档判断，star 数和别的项目采用不证明功能正确或安全。

当你学习完了理论部分，这里给出一个非常好的实战例子。有些同学问我，有没有推荐的开源的学习Agent的项目啊？那我的回答就是使用这个Pi-Agent。为什么？因为它足够简单，好上手。但是具备Agent项目的最核心的要素。同时他又支持扩展，官方给了很多扩展的例子。你通过这个项目，可以快速学习Agent，也给了你丰富的资料和空间去扩展，改造成自己的项目。另外他也足够权威，github上有快60k 的stars。包括也有博主说，Openclaw也就是使用它改造的，所以权威性和可学习性也不用担心。当然我们项目还有解析Hermes,解析Openclaw,ClaudeCode。 我的建议是先看这个项目，看明白再看其他的，因为其他项目复杂太多。

5.1 总述

5.1.1 Pi 是什么,

Pi 是一个很小的、可以自我扩展的 Agent Harness，也就是 Agent 运行框架。它的产品口号是 "grows with you"。直白一点说，就是先给你一个很小的内核，后面缺什么再加什么。

更正：本课采用早期小内核快照；当前 Pi 已提供 MCP 接入。复现时固定版本，再确认默认工具、扩展与 MCP 配置。

查看解释与参考资料

这是旧版快照的功能描述。当前官方 Pi 仓库已迁至 earendil-works/pi，并提供内建 MCP 配置和 stdio/Streamable HTTP 接入文档，不能继续作为无版本结论。

Pi 官方 MCP 文档 ↗

刚装好的 Pi 很克制：默认只有 4 个工具，分别是 read、bash、edit、write；系统提示词大约 20 行；没有 MCP，没有子代理，没有权限弹窗，没有 plan 模式，也没有内置 todo。第一次看会觉得功能少，但这正是它的设计选择：内核只保留必要部分，其他能力通过扩展补上。你缺一个能力，就可以让 Pi 写一个 TypeScript 扩展把它接进去。

Pi 是 TypeScript monorepo，主要由 4 个 package 组成：

- pi-ai：多供应商 LLM API 抽象，覆盖 OpenAI、Anthropic、Google、Bedrock 等。

更正：pi-agent-core 提供工具执行、状态与事件循环；会话持久化与自动压缩由上层 coding-agent 组织，路径随版本核对。

查看解释与参考资料

工具调用与状态管理属于 core；当前文档将会话存储和压缩策略放在 coding-agent 的 core 目录，不宜把本课四包图当完整且永久的职责清单。

Pi 官方包与运行时说明 ↗

- pi-agent-core：Agent 运行时，包含工具调用、状态管理、会话和压缩。

- pi-coding-agent：面向编码场景的交互式 CLI。

- pi-tui：自研终端 UI 库，支持差分渲染。


5.1.2 Pi 与 Claude Code 的主要区别

Pi 选择"小内核加扩展"，Claude Code 选择"默认带齐常用功能"。这个差异会影响工具数量、权限模型、提示词长度、扩展方式和会话结构。下面按维度对比，每条都先说 Pi、再说 Claude Code：

5.1.3 为什么 Pi 适合学习

我认为这个项目特别适合，你在学完Agent理论之后，第一个学习的实践项目。不论你是想要阅读开源代码，还是说找一个项目改装，扩展，这个项目都太合适了。

Pi 是一个很合适的样本。原因主要有四个：

  1. 内核小，能读完。Claude Code 这类功能密集的工具，新手容易迷失在边缘功能里。Pi 的主干就是 agent loop，入口集中，读起来更容易抓住脉络。别看他小，但他五脏俱全。基本上面试Agent岗位的时候，围绕记忆，压缩，会话恢复，Agent Loop(React)这些是面试最常考的点，这些都有。即使他不算很复杂，但是你学会了以后，对于一个Coding Agent整体的架构的意识思想是完备的。
  1. Agent loop 是手写的。市面上有 OpenAI Agents SDK、Vercel AI SDK 这类框架，导入后很快就能跑，但很多关键步骤被封装起来了。Pi 把初始化、压缩、模型调用和工具循环都写在明面上，更适合学习。
  1. 模块边界清楚。4 个 package 各管一块，内核和交互层分开。Agent Core 可以脱离终端，被 RPC 或 SDK 调用，所以读一层时不必同时理解所有 UI 细节。
  1. 他的思想"grows with you"，太适合你去改造了，添加了。比如他没有Plan功能，没有MCP功能。都适合你一边用，一边学，一边改造和扩展。

    Agent
    围绕目标读取状态、选择动作、观察结果并判断是否继续的程序。行动权限与停止条件需要明确设计。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    LLM
    通过训练学习语言规律、根据上下文生成内容的模型；输出可用性和事实正确性仍需要检查。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Prompt
    向模型提供任务、上下文、约束和输出要求的输入内容；提示本身不能代替程序权限校验。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    工具调用
    模型或策略提出结构化的操作请求，由程序校验参数与权限、执行工具并返回结果。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    记忆
    为后续使用保留信息的机制。近期会话、跨会话偏好与操作审计的范围和用途应分开。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    MCP
    连接模型应用与工具、资源等能力的协议。协议一致性不代替工具授权或业务安全检查。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    API
    程序之间约定的调用入口，包括输入、返回和错误处理。是否可用依赖具体实现、权限和环境。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    SDK
    帮助调用某种平台能力的一组开发工具或库。SDK 版本与服务端 API 版本需要区分。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    ReAct
    把决策与动作、外部观察交替组织的一类 Agent 模式。外部轨迹与模型内部思考并不等同。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    命令行
    通过文本命令操作程序的界面。先确认当前目录、输入参数和命令的实际副作用。本站通用释义；具体接口以适用版本为准。 回看本课上下文
