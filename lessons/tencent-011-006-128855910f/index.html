重规划：替换未执行队列，而不是继续旧清单

  • 分开已完成记录与待执行队列
  • 说明重新赋值为什么不一定改变正在迭代的列表
  • 根据失败观察替换剩余任务，并设置退出预算
卡住时，先补哪一小节？
  • 调用、结果和观察

计划不是已经发生的事实

把计划分为completed和pending：completed记录已经核对的执行结果，pending在本例中先存放模型提出的候选任务，尚未全部获准执行。用户只授权查询，B订位、C发送确认从提案阶段就已越权；即使A查到有位，也不能执行B或C。A实际查到无位后，旧订位方案还多了一项前提失效的原因。保留真实观察，取消这些候选，再产生授权范围内的路径。

更新变量和更新调度器不是同一件事

for step in plan开始时，迭代器已经指向一个列表。循环内部把plan赋成新列表，并不自动让那个迭代器改读新对象。用显式队列逐次取下一项，在每次取任务前读取当前pending，才能看清替换效果；执行器还必须独立检查授权和当前前提。下方Python只模拟任务名、队列替换与步数，不调用工具，也未实现授权检查，不能直接当作安全执行器。

允许调整，也要保证可以停下来

重规划需要次数、步数或时间上限，并检查重复的输入与观察。达到上限时报告已完成和未解决部分。队列更新不授予新权限：查询有结果后仍须取得明确的订位、发送授权，才能提出相应执行步骤。不要把取消的任务标记为完成，也不能把“自动调整计划”当成扩大执行权限的理由。

把输入代进去，走一遍

以下是本站固定教学样例，用来观察规则，不是线上服务的测量结果。

虚构模型初始提案A=查18点；B=订18点；C=发18点确认。用户只授权查询18点或19点，未授权订位或发送；所以B、C从一开始就不能执行，即使A查到有位也一样。本次A观察为无位，替换后的任务D=查19点、E=汇总可选时间；不创建预订。总步数上限4，重规划上限1。

步骤当前内容或状态为什么这样变化
1 · 检查初始提案completed=[]；pending=[A,B,C]pending此时是候选提案；只放行获准的查询A。B、C未获授权，已被拦截，不能因排在队列里而执行。
2 · 执行 Acompleted=[A:无位]；pending=[B,C]保存真实查询观察；B、C仍是被拦截的候选，此外订18点的可用性前提也已失效。
3 · 替换剩余任务cancelled=[B,C]；pending=[D,E]；replans=1将越权且前提失效的候选正式记为取消，换成获准的查询和汇总；不能继续沿旧迭代器执行B、C。
4 · 执行 Dcompleted=[A:无位,D:有2位]；pending=[E]查询19点仍在授权范围内。
5 · 执行 Ecompleted增加汇总；pending=[]；steps=3报告可选时间，队列为空即正常结束；未产生预约副作用。

最后得到：实际执行A、D、E，共3步；B、C因未获授权从未执行，并非仅因无位才取消。完成记录与取消记录分别保留，不能说旧三步提案全部完成。

查看完整 Python 推导与预期输出

标准库教学程序。固定输入的输出会随课程构建核对；不访问模型或外部服务。

pending = ["A", "B", "C"]
completed, cancelled = [], []
replans, steps = 0, 0
while pending and steps < 4:
    task = pending.pop(0)
    completed.append(task)
    steps += 1
    if task == "A" and replans < 1:
        cancelled.extend(pending)
        pending = ["D", "E"]
        replans += 1
print(completed)
print(cancelled, replans, steps)

预期输出：

['A', 'D', 'E']
['B', 'C'] 1 3

如果这一步出错呢？

触发条件：在for循环中plan=[D,E]，却继续使用原迭代器，并省略逐项授权检查。

错误执行器在A完成后改变变量plan，但仍从旧迭代器拿到B → 未经授权提交预约，且本次已知无位 → 再未经授权执行C。即使A有位，后两项也仍然越权。

恢复方法：每次调度前读取当前队列，独立核对授权与当前前提；替换时废止未获授权或已失效的任务及其依赖。订位和发送须另获明确授权，不能靠重规划放行。保存已完成结果、重规划依据和预算，到达上限则结束并报告未解决项。

换个条件，自己判断

先设D也返回无位且重规划次数已达1：应再增加F继续找，还是停止汇总？说明已完成、取消和未解决的内容。再改成A查到有位：B、C能否直接执行，为什么？

先口述、画两行状态或改一个值即可。检查方法在提交小测后也可以回来核对。

想完后，对照检查方向
  • 不突破已设重规划预算，保留A和D的查询结果
  • 有位仍不等于获准订位或发送，B、C须另获明确授权
  • 无位是可报告结果，不伪造预约成功

Plan-and-Execute Agent 实现

更正：改用显式剩余任务队列或带预算的调度循环；重规划后替换待执行队列，保留已完成记录并重新验证依赖与权限。

当前 for 仍遍历旧 plan.steps；只改 plan 变量不会执行新计划。

class PlanAndExecuteAgent:
 """
    Plan-and-Execute 架构的 Agent
    核心机制：先完整规划，再按计划执行
    """

 def __init__(self, planner, executor):
 # 规划器：负责制定执行计划
        self.planner = planner
 # 执行器：负责执行具体步骤
        self.executor = executor

 def run(self, task):
 """
        执行任务
        分为规划阶段和执行阶段
        """
 # ==================== 规划阶段 ====================
 # 一次性生成完整的执行计划
        plan = self.planner.create_plan(task)

 # ==================== 执行阶段 ====================
        results = []

 # 按计划顺序执行
 for step in plan.steps:
 # 执行当前步骤
            result = self.executor.execute(step)
            results.append(result)

 # 检查是否需要重新规划
 # 例如：执行结果与预期不符，或出现意外情况
 if self.needs_replan(results):
 # 基于当前结果重新规划
                plan = self.planner.replan(task, results)

 # 整合所有结果
 return self.summarize(results)

 def needs_replan(self, results):
 """
        判断是否需要重新规划
        检查执行结果是否符合预期
        """
 # 获取最后一个结果
        last_result = results[-1]

 # 如果结果明显不符合预期，需要重规划
 if last_result.is_unexpected():
 return True

 # 如果结果导致后续步骤无法执行，需要重规划
 if last_result.blocks_future():
 return True

 return False


class Planner:
 """规划器：生成任务执行计划"""

 def create_plan(self, task):
 """创建初始执行计划"""
        prompt = f"""
任务：{task}

请制定详细的执行计划，包括：
1. 需要执行的步骤顺序
2. 每个步骤的具体操作
3. 步骤之间的依赖关系

输出格式：
步骤1: [操作描述]
步骤2: [操作描述]
...
"""
        plan_text = self.llm.generate(prompt)
 return Plan.parse(plan_text)

 def replan(self, task, results):
 """基于执行结果重新规划"""
 # 分析已完成的结果
        completed = [r for r in results if r.is_success]
        failed = [r for r in results if not r.is_success]

 # 生成调整后的计划
        prompt = f"""
原始任务：{task}
已完成步骤：{completed}
失败步骤：{failed}

请制定调整后的执行计划：
"""
        plan_text = self.llm.generate(prompt)
 return Plan.parse(plan_text)


class Executor:
 """执行器：执行具体的计划步骤"""

 def execute(self, step):
 """执行单个步骤"""
 # 根据步骤类型选择执行方式
 if step.type == "tool_call":
 return self.execute_tool_call(step)
 elif step.type == "code":
 return self.execute_code(step)
 elif step.type == "query":
 return self.execute_query(step)

 return Result(success=False, error="Unknown step type")

注意：Plan-and-Execute 模式适合任务结构相对稳定、可以提前规划的场景。对于需要灵活应变的环境，ReAct 模式可能更合适。

章节小结

本章节介绍了 AI Agent 的推理与规划核心能力。

ReAct 框架通过推理与行动的循环，让 Agent 能够边执行边调整策略。

思维链（CoT） 通过展示逐步推理过程，提升复杂任务的执行准确性。

思维树（ToT） 扩展了思维链，支持多路径探索和回溯。

MCTS 是一种启发式搜索算法，适合复杂决策和规划问题。

Reflexion 赋予 Agent 自我反思能力，从失败中学习和改进。

任务分解策略 是规划能力的基础，包括递归分解、平行分解和层次分解。

Plan-and-Execute 采用先规划后执行的模式，适合结构稳定的任务。

这些技术可以单独使用，也可以组合使用，构建更强大的 Agent 系统。

 """
    Plan-and-Execute 架构的 Agent
    核心机制:先完整规划,再按计划执行
    """

 def __init__(self, planner, executor):
 # 规划器:负责制定执行计划
        self.planner = planner
 # 执行器:负责执行具体步骤
        self.executor = executor

 def run(self, task):
 """
        执行任务
        分为规划阶段和执行阶段
        """
 # ==================== 规划阶段 ====================
 # 一次性生成完整的执行计划
        plan = self.planner.create_plan(task)

 # ==================== 执行阶段 ====================
        results = []

 # 按计划顺序执行
 for step in plan.steps:
 # 执行当前步骤
            result = self.executor.execute(step)
            results.append(result)

 # 检查是否需要重新规划
 # 例如:执行结果与预期不符,或出现意外情况
 if self.needs_replan(results):
 # 基于当前结果重新规划
                改用显式剩余任务队列或带预算的调度循环；重规划后替换待执行队列，保留已完成记录并重新验证依赖与权限。

 # 整合所有结果
 return self.summarize(results)

 def needs_replan(self, results):
 """
        判断是否需要重新规划
        检查执行结果是否符合预期
        """
 # 获取最后一个结果
        last_result = results[-1]

 return False

 """创建初始执行计划"""
        prompt = f"""
任务:{task}

请制定详细的执行计划,包括:
1. 需要执行的步骤顺序
2. 每个步骤的具体操作
3. 步骤之间的依赖关系

输出格式:
步骤1: [操作描述]
步骤2: [操作描述]
...
"""
        plan_text = self.llm.generate(prompt)
 return Plan.parse(plan_text)

 def replan(self, task, results):
 """基于执行结果重新规划"""
 # 分析已完成的结果
        completed = [r for r in results if r.is_success]
        failed = [r for r in results if not r.is_success]

 # 生成调整后的计划
        prompt = f"""
原始任务:{task}
已完成步骤:{completed}
失败步骤:{failed}

请制定调整后的执行计划:
"""
        plan_text = self.llm.generate(prompt)
 return Plan.parse(plan_text)
