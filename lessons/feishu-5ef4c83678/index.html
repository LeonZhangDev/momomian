1.1 LLM是如何被训练出来的

1. 构建基础模型（构建通用大模型）

  • 更正：预训练（Pre-training，通常使用自监督目标，例如下一 Token 预测）。

    查看解释与参考资料

    大模型常见下一 Token 预测使用文本自身构造目标，写自监督更准确。

    预训练（Pre-training，非监督）
◦
使用海量的通用、未标注数据（如网页、书籍、代码等）。
◦
目标是让模型具备语言理解、推理、世界知识等通用能力。
  • 微调（SFT）
◦
使用指令-响应数据、任务特定数据、人工标注数据。
◦
让模型学会遵循指令，更贴近实际应用。
  • 对齐（如 RLHF、DPO）
◦
基于人类偏好数据，通过奖励模型或偏好分数进行优化。
◦
目的是让模型输出更符合人类价值观和安全要求。

2. 微调基础模型（提升指定场景性能）

  • 从通用 LLM/SLM 出发，模型已经具备：
◦
语言能力、推理能力、世界知识、聊天、指令跟随、代码能力等。
  • 再次进行：
◦
微调（SFT）：针对特定领域或任务的数据。
◦
对齐（RLHF、DPO）：确保输出符合特定用户或行业需求。
  • 最终得到针对特定场景优化的模型。

1.2 Function calling是如何被训练出来的

更正：工具调用能力可通过包含工具定义、调用参数和结果的示例进行训练，并可结合偏好优化；具体阶段与方法取决于模型训练方案。

查看解释与参考资料

这是一条可能路径，不是所有工具调用模型都必须经历的固定三步，RLHF 也并非工具调用能力的必要条件。

Function calling是通过在模型训练的预训练阶段使用自监督学习，在微调阶段使用SFT技术，以及在对齐阶段使用RLHF技术来使模型具有能够理解用户意图并生成函数结构化的函数调用请求的能力。

具体来讲：

预训练阶段的自监督学习使得模型能够理解自然语言。

微调阶段的SFT技术使用标注数据让模型理解何时该调用函数，调用函数的格式是什么。

对齐阶段使用RLHF，使用人类的反馈来优化调用结果，使模型的调用更符合人类的习惯。
