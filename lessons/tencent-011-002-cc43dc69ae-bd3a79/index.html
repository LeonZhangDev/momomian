先看本单元主讲：工具调用（Function Calling）

跟着一组输入，学完这一步

工具调用：两次模型请求之间究竟发生了什么

  • 按调用ID连接请求、参数、执行结果和观察
  • 说明模型提出调用与应用真正执行的区别
  • 处理未知工具、缺参和同名多次调用

本单元的 3 篇材料共用这组串讲、小测和新卡。切换资料页不会产生重复的题目记录。

卡住时，先补哪一小节？
  • 一次模型请求
  • 输出三层校验

模型生成调用意图，应用控制执行

模型返回工具名与参数，应用才负责确定该工具是否允许、参数是否符合约定、当前用户是否有权访问对象。工具可见并不等于任意调用都被授权。本例只做预约余位查询，没有真实预订；“查到2个空位”不能写成“已预约成功”。

调用ID比工具名更能区分这一笔结果

同一个 query_slots 可以同时查询两个时间。a查18点、b查19点，即使工具名相同，返回也必须绑定各自ID和参数。不能把最后一个结果按工具名覆盖到前一个，也不能让一个调用的观察回答另一个调用。ID是否由模型接口提供、字段叫什么，按具体接口约定实现。

把真实观察交回去，第二次请求才有依据

应用保存助手发出的完整调用记录，追加与调用关联的工具观察，再发送下一轮模型请求。模型可根据观察回答、补参、改计划或停止。工具错误也作为错误观察保留，不改成成功。调用轮数与工具次数都要受预算限制；外部写动作还需要确认、幂等键和回执。

把输入代进去，走一遍

以下是本站固定教学样例，用来观察规则，不是线上服务的测量结果。

虚构用户：“2026-11-10，两人，18点和19点哪个有位置？”固定调用：a=query_slots(date=2026-11-10,time=18:00,people=2)，b=query_slots(date=2026-11-10,time=19:00,people=2)。假工具结果 a:available=0，b:available=2。

步骤当前内容或状态为什么这样变化
1 · 第一轮模型请求user消息+query_slots工具定义模型可选择提出调用，但尚未访问查询服务。
2 · 记录调用a→18:00；b→19:00保存ID、工具名和参数；同名不合并。
3 · 放行前检查工具在白名单；日期、人数、时间及用户范围通过人数应是约定整数而非bool，缺日期不擅自默认今天。
4 · 应用执行查询a.available=0；b.available=2这是应用执行得到的固定教学观察，不由模型凭空填入。
5 · 追加工具观察观察a绑定调用a；观察b绑定调用b保留原调用消息，按接口要求加入对应结果。
6 · 第二轮模型请求请求含原问题、两次调用和对应观察模型现在才能基于结果生成答复，或在预算内继续。
7 · 核对最终答复“18点无位，19点有2个空位；尚未预约。”保留查询与预订的区别，不能跨过授权直接提交。

最后得到：本次完成两次余位查询，没有创建预约。a和b的观察分别保留，最终答复可按原输入逐项检查。

如果这一步出错呢？

触发条件：按工具名存结果，或未校验就动态执行模型提供的名字。

results["query_slots"]先存0后被2覆盖 → 最终把18点也说成有位；若工具名变成delete_booking，直接执行还会越过允许范围。

查看解释与参考资料

类型校验出错后仍无条件运行范围比较；数值字段传字符串或 None 时可能抛异常。入口也应先确认 params 为对象。

class ParameterValidator:
 """参数验证器"""

 def __init__(self, tool_def):
        self.tool_def = tool_def

 def validate(self, params):
 """执行完整的参数验证"""
        all_errors = []

 # 检查必填参数
        required_errors = self.validate_required(params)
        all_errors.extend(required_errors)

 # 检查参数类型
        type_errors = self.validate_type(params)
        all_errors.extend(type_errors)

 # 检查参数范围
        range_errors = self.validate_range(params)
        all_errors.extend(range_errors)

 # 检查额外参数（未定义的参数）
        extra_errors = self.validate_extra(params)
        all_errors.extend(extra_errors)

 return len(all_errors) == 0, all_errors

 def validate_required(self, params):
 """验证必填参数"""
        errors = []
        required_params = self.tool_def["parameters"].get("required", [])

 for param_name in required_params:
 if param_name not in params or params[param_name] is None:
                errors.append(f"缺少必填参数: {param_name}")

 return errors

 def validate_type(self, params):
 """验证参数类型"""
        errors = []

 for param_name, param_value in params.items():
 if param_name in self.tool_def["parameters"]["properties"]:
                param_def = self.tool_def["parameters"]["properties"][param_name]
                expected_type = param_def.get("type")

 if expected_type == "string" and not isinstance(param_value, str):
                    errors.append(f"参数'{param_name}'应为字符串类型，实际为{type(param_value).__name__}")
 elif expected_type == "integer" and not isinstance(param_value, int):
                    errors.append(f"参数'{param_name}'应为整数类型，实际为{type(param_value).__name__}")
 elif expected_type == "number" and not isinstance(param_value, (int, float)):
                    errors.append(f"参数'{param_name}'应为数字类型，实际为{type(param_value).__name__}")
 elif expected_type == "boolean" and not isinstance(param_value, bool):
                    errors.append(f"参数'{param_name}'应为布尔类型，实际为{type(param_value).__name__}")

 return errors

 def validate_range(self, params):
 """验证参数范围"""
        errors = []

 for param_name, param_value in params.items():
 if param_name in self.tool_def["parameters"]["properties"]:
                param_def = self.tool_def["parameters"]["properties"][param_name]

 # 检查最小值
 if "minimum" in param_def and param_value < param_def["minimum"]:
                    errors.append(f"参数'{param_name}'不能小于{param_def['minimum']}")

 # 检查最大值
 if "maximum" in param_def and param_value > param_def["maximum"]:
                    errors.append(f"参数'{param_name}'不能大于{param_def['maximum']}")

 # 检查枚举值
 if "enum" in param_def and param_value not in param_def["enum"]:
                    errors.append(f"参数'{param_name}'必须是{param_def['enum']}中的一个")

 return errors

 def validate_extra(self, params):
 """检查未定义的额外参数"""
        errors = []
        defined_params = set(self.tool_def["parameters"]["properties"].keys())
        provided_params = set(params.keys())

        extra_params = provided_params - defined_params
 if extra_params:
            errors.append(f"提供了未定义的参数: {', '.join(extra_params)}")

 return errors

# 使用示例
validator = ParameterValidator(weather_tool)
params = {"city": "北京", "date": "明天", "extra": "不应该有的参数"}
is_valid, errors = validator.validate(params)

if is_valid:
 print("参数验证通过")
else:
 print("参数验证失败:")
 for error in errors:
 print(f"  - {error}")

参数提取与验证的完整流程

参数修正策略

当参数验证失败时，可以采取以下策略：

  • 询问用户：直接向用户询问缺失或错误的参数
  • 使用默认值：对于可选参数，使用预定义的默认值
  • 智能推断：根据上下文推断合理的参数值
  • 格式转换：将用户提供的格式转换为工具要求的格式

更正：仅执行已约定且无歧义的格式转换；缺失或语义不明的字段应澄清，修正后再次执行全部校验。
