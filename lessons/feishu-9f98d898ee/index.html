本课MCP兼容性讨论中，初始化后发现某能力未声明支持，应如何处理？ 结论：按实际协商结果禁用、回退或提示，不盲目调用。 理由：协议连接不仅是网络通，版本与能力帮助明确可用范围，具体初始化规则应以接入版本为准，不能从握手成功推断全部可选功能已实现。 配套示例：服务端未声明订阅能力时，客户端不要直接发起资源订阅而不处理失败。 按本课MCP与A2A对照，两者主要关注什么不同连接？ 结论：MCP偏Agent与工具数据，A2A偏独立Agent协作。 理由：工具数据连接关心发现和调用具体能力，Agent互操作更关心任务协作与内部实现封装，服务可能提供不同入口，应按对外契约选择，而不只看内部是否用了模型。 配套示例：天气查询若暴露为工具可按工具契约调用；委托独立研究任务则关注任务协作语义。

4.再问一个MCP的问题，我们如果使用了MCP Client + 远程的Server，本地的Client 和远端Server 会有交互，如何解决他们之间协议不兼容的问题。具体是什么意思呢？比如你用了微软的开发框架，开发了一个智能体，它里面的MCP的实现未必是最新版本的MCP 实现，也有可能是自己的MCP实现就不完整，那么server和client之间可能会有一些不兼容的问题，你是如何考虑这个问题以及如何避免的？

4.1 是这样的，这个问题的出发点是其实你使用的MCP Server 未必是由你们团队维护的，比如说你是一个天气查询服务，但是你需要使用它，由你们公司设计的client会和它交互，这个时候可能会有一些兼容性问题，比如openai的sdk 它其实在MCP的实现上就不完整，这时怎么办？

（这个题问得太细致了，我觉得可能是面试官做项目的时候自己遇到过的工程问题，没有对应的经验我觉得还挺难回答的，通过这个题我们要知道MCP 协议里 的两个能力： 版本协商 和 能力协商）

MCP 标准协议本身就定义了两个关键机制：

  1. 版本协商（Version Negotiation）
◦
在连接初始化阶段，客户端和服务器会交换它们支持的协议版本列表，并选定一个双方都支持的版本。如果没有交集，连接会优雅失败。
◦
这意味着客户端可以明确知道“是否匹配”，并在不匹配时采取回退或提示。
  1. 能力协商（Capabilities Negotiation）
◦
握手时，双方会声明自己支持的功能（如 sampling、resources.subscribe 等）。客户端可以根据服务器返回的能力决定启用哪些功能，避免调用未实现的能力。

所以，客户端在初始化握手后就能拿到：

◦
协议版本（是否兼容）
◦
支持的能力列表（哪些功能可用）

如果发现不匹配，客户端可以：

◦
回退到兼容版本（如果支持多版本）
◦
禁用不支持的功能（避免调用导致错误）
◦
或直接提示用户“当前服务端不兼容，需要升级或切换”。

5 MCP 和 A2A之间有一些什么样的异同，各自适用于什么样的场景。

(A2A 协议目前有两个面试中出现了，之前认为不怎么考，现在还是会考的，所以我把A2A的概念补充在上面笔记Agent 部分MCP下面了。 A2A的基本概念大家还是需要知道的，另外针对于这个MCP 和 A2A的异同，复习了笔记的A2A和MCP的概念，相信此题应该很好回答）

MCP解决的是 "Agent ↔ 工具/数据" 的标准化连接问题：让 Agent 以统一的方式发现、鉴权并调用外部工具、API、数据库、文件系统等能力。就像给 AI 装一个“USB‑C 工具口”。

A2A解决的是 "Agent ↔ Agent" 的互操作与协作问题：不同厂商、不同框架下实现的多个智能体之间，如何发现彼此、交换消息/任务、长时协作并保持内部实现不透明。


5.1 我现在有一个Agent，他对外既可以使用A2A这种方式提供服务，也可以使用MCP Server的能力提供服务，这个时候怎么选？

5.2 是这样的，Agent自身内部是怎么思考如何实现你的服务的，比如你是一个天气服务，对于使用者来说，我不care你内部是如何实现的，我就是让你去查询过去几天的天气，你可以使用工具去调用，也可以使用Agent的方法去获取这个天气，这个时候呢，MCP还是A2A?

    本课命中的术语参考

    从全文匹配本站通用术语表，并摘录少量原文定义。未列出的专有词需继续查证。

    Agent
    围绕目标读取状态、选择动作、观察结果并判断是否继续的程序。行动权限与停止条件需要明确设计。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    MCP
    连接模型应用与工具、资源等能力的协议。协议一致性不代替工具授权或业务安全检查。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    HTTP
    客户端与服务端交换请求和响应的协议；方法、状态码、响应体和业务结果分别提供信息。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    API
    程序之间约定的调用入口，包括输入、返回和错误处理。是否可用依赖具体实现、权限和环境。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    SDK
    帮助调用某种平台能力的一组开发工具或库。SDK 版本与服务端 API 版本需要区分。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    缓存
    保存可复用结果以减少重复工作。命中率、键的范围、失效与更新策略会影响正确性。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    LRU
    按最近使用顺序选择淘汰对象的缓存策略；需要定义什么操作会更新使用顺序。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    Q/K/V
    注意力计算中常用的查询、键和值表示；它们的含义依赖具体张量来源与计算位置。本站通用释义；具体接口以适用版本为准。 回看本课上下文
    命令行
    通过文本命令操作程序的界面。先确认当前目录、输入参数和命令的实际副作用。本站通用释义；具体接口以适用版本为准。 回看本课上下文
