中间输出也是需要检查的数据

中文资料助手先抽取事实，再匹配要求，最后写说明。原文“会 Python，年限未填写”只能支持技能字段，不能支持“三年工作经验”。如果抽取阶段补造了年限，后面即使按步骤认真匹配，也会把错误继续放大。让字段携带原句和缺失状态，交接时才有依据。

校验点应放在污染扩大之前

本例约定未知年限保留为 null，不能当作0年，也不能替人补年限。匹配器只给出“技能符合、年限待确认”。最终说明继承这个状态，邀请对方补充信息。多拆几个提示词不会自动修复事实来源，重要的是每一步的契约与拒绝条件。

虚构原文“会 Python，年限未填写”。规则要求 Python 且年限≥2。v1 抽取 skills=[Python],years=3；v2 抽取 skills=[Python],years=null,evidence="年限未填写"。教学开发集4例：v1正确2例、v2正确4例；留出集2例：v1正确1例、v2正确1例。

步骤当前内容或状态为什么这样变化
1 · 核对原文技能=Python；年限=未知未知不等于0，也不等于3。
2 · 比对中间输出v1 years=3 没有证据；v2 years=null 有原句在抽取交接处拒绝无依据的数字，不等到最终说明再找错误。
3 · 判断条件技能符合；年限条件无法判定保留待确认状态，不能因为已有一项符合就判定全部通过。
4 · 生成说明“已看到 Python 技能；请补充相关年限。”最终文字引用可支持的事实并说明缺口。
5 · 分开看样本开发：2/4→4/4；留出：1/2→1/2开发集改善不等于留出表现提高，2个留出样本也不足以推断普遍效果。

最后得到：修订链路不再把缺失年限编成3年。给定结果只能说明开发样例改善、留出集未提高，不能包装成“准确率全面提升”。

如果这一步出错呢？

触发条件：下游把抽取器的每个字段都视为已核实事实。

年限未填 → 被补成3年 → 3≥2 → 说明写“已有三年经验”。格式始终正确，但每一步都在沿用同一项无依据数字。

恢复方法：中间结构增加证据和缺失状态；不通过的事实不进入确定性结论。错误归类为抽取臆造、字段契约缺失或匹配逻辑错误后，再决定修改哪一层。

提示词链（Prompt Chaining）

当一个任务过于复杂，单条提示词无法可靠完成时，可以把它拆分成多个子任务，依次执行，前一步的输出作为下一步的输入——这就是提示词链（Prompt Chaining）。

为什么需要提示词链？

把所有要求塞进一个超长提示词，会导致以下问题：

  • AI 容易遗漏某些子任务
  • 前后步骤的逻辑相互干扰
  • 出错时难以定位问题在哪一步
  • Token 消耗高，成本上升

提示词链把复杂任务分而治之，每一步都能独立验证质量，整体可靠性大幅提升。


适合使用提示词链的场景
