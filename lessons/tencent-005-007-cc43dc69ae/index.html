客户端配置像收件地址，请求正文像申请表

本例沿用百炼兼容的 Chat Completions 消息形状。客户端配置包含后端持有的凭据、对应地域的 base_url 和超时；请求正文包含模型名、messages 与输出上限。把模型名写进正文不等于该账号有权使用它，也不保证这个接口支持全部同名参数。凭据不进入网页、示例响应或日志。

SDK 对象、JSON 字典和业务结果是三层

HTTP 正文到达后，SDK 往往把它包装成带属性的对象。使用 SDK 时可能读取 completion.choices[0].message.content；本页离线代码为了看清字段，读取等价的字典键。两种访问方式不能混抄。得到 content 后，应用仍要检查它是否为空、是否满足当前任务。

一次只学清一种接口，再看差异

本例只追踪 Chat Completions。Responses 接口常通过 output 或 SDK 的 output_text 便利属性取得结果，不能把 choices 路径原样搬过去。本例不发送请求，固定 response 也不证明提供商接通。实际接入前要核对账号地域、模型能力和接口文档。

把输入代进去，走一遍

以下是本站固定教学样例，用来观察规则，不是线上服务的测量结果。

虚构任务：用户说“用一句话问候”。请求正文为 {model:"课堂模型",messages:[{role:"user",content:"用一句话问候"}],max_tokens:16}；固定响应 status=200，choices[0].message.content="你好，欢迎学习！"，finish_reason="stop"。

步骤当前内容或状态为什么这样变化
1 · 组装messages 长度为 1；stream=false确认只有本次教学输入；客户端配置不混进公开消息。
2 · 收到正文HTTP 200；choices 长度为 1先确认获得可解析正文，再检查候选项存在；200 不是字段校验的替代品。
3 · 提取文本content="你好，欢迎学习！"；finish_reason="stop"这里是普通文本响应。工具调用、拒答、截断或空候选需要另外的处理分支，不能一律取第一个 content。
4 · 交给页面业务结果 {ok:true,text:"你好，欢迎学习！"}文本非空且符合一句问候的教学要求，才交给显示层。原响应和业务结果分开保存，便于排查。

最后得到：页面可显示“你好，欢迎学习！”。只能得出这个固定响应通过了字段和非空检查，不能据此宣称真实账号、所有模型或所有错误已验证。

查看完整 Python 推导与预期输出

标准库教学程序。固定输入的输出会随课程构建核对；不访问模型或外部服务。

response = {"choices": [{"message": {"content": "你好，欢迎学习！"}, "finish_reason": "stop"}]}
choices = response.get("choices", [])
text = choices[0]["message"].get("content") if choices else None
ok = isinstance(text, str) and bool(text.strip())
print({"ok": ok, "text": text if ok else None})

预期输出：

{'ok': True, 'text': '你好，欢迎学习！'}

如果这一步出错呢？

触发条件：把 Responses 返回当作 Chat Completions，或只凭 HTTP 200 直接访问 choices[0]。

正文只有 output → 找不到 choices；或 choices=[] → 第 0 项不存在。若 catch 后返回“成功”，用户会得到空结果。

恢复方法：先按所调用接口选解析器；空候选明确报“没有可用文本”。401 核对后端配置而不回显凭据；模型不可用核对名称、地域与权限；超时先区分读取任务和可能带副作用的任务，再按预算恢复。
