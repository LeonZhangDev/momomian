先写清这个问题需要哪些证据

问题是“2026标准版退款期限及已使用服务的例外是什么”。教学标准相关集合为{d2,d4}。六个文档：d1=2025标准版14天，d2=2026标准版7天，d3=2026专业版30天，d4=2026标准版已使用服务例外，d5=无规则的营销介绍，d6=发票抬头说明。所有文字与排名为固定教学数据。

融合比较名次，重排比较候选与问题

本例BM25排名[d1,d2,d3,d4]，向量排名[d3,d4,d2,d5]。RRF用k=1便于手算，每路同一ID只算一次，分数为各路1/(1+rank)之和。真实应用常需要另选k并评估，不能把教学值当通用推荐。融合后的Top2仍可能排错；重排只能调整拿到的候选，找不回根本没进入候选池的证据。

改善多少，要和成本一起比较

以相同Top2和相关集合比较：向量Top2命中1/2，融合Top2仍命中1/2；从融合Top4重排后Top2命中2/2。重排分数为本页给定值，不是真实模型能力测量。假定向量4ms、融合加1ms、重排再加6ms，则总耗时4、5、11ms；这只练习计算与取舍，不能推出生产性能。

把输入代进去，走一遍

以下是本站固定教学样例，用来观察规则，不是线上服务的测量结果。

固定排名：BM25=[d1,d2,d3,d4]；vector=[d3,d4,d2,d5]；相关集合={d2,d4}。融合k=1。同分按ID升序。重排给分d2=.94、d4=.86、d3=.40、d1=.20、d5=.10。

步骤当前内容或状态为什么这样变化
1 · 只看向量Top2[d3,d4]；命中d4；precision=recall=1/2d3年份对但版型错。相关集合有2项，返回也2项，所以这一次两指标数值相同。
2 · 计算融合d3=1/4+1/2=.75；d2=1/3+1/4=7/12≈.5833每路名次从1起；不同来源的原始分数不直接相加。
3 · 继续核算d4=1/5+1/3≈.5333；d1=.5；d5=.2融合顺序为[d3,d2,d4,d1,d5]，Top2仍只命中1项。
4 · 重排候选融合Top4=[d3,d2,d4,d1] → [d2,d4,d3,d1]使用给定的重排分数，Top2现在同时包含期限和例外。d6没召回，也没有被重排凭空造出。
5 · 质量与代价Top2命中1→1→2；假设耗时4→5→11ms在相同样本和返回数下比较。仅这个问题的改善不能代表总体提升。

最后得到：最终候选d2与d4分别支持期限和例外。这个例子说明：融合不保证第一名正确；重排若要发挥作用，相关证据必须进入其候选池。还需检查版本、版型和权限。

标准库教学程序。固定输入的输出会随课程构建核对；不访问模型或外部服务。

from fractions import Fraction

rankings = [["d1", "d2", "d3", "d4"], ["d3", "d4", "d2", "d5"]]
scores = {}
for ranking in rankings:
    seen = set()
    for rank, doc in enumerate(ranking, 1):
        if doc not in seen:
            scores[doc] = scores.get(doc, Fraction(0)) + Fraction(1, 1 + rank)
            seen.add(doc)
for doc in sorted(scores, key=lambda item: (-scores[item], item)):
    print(doc, format(float(scores[doc]), ".4f"))

预期输出：

d3 0.7500
d2 0.5833
d4 0.5333
d1 0.5000
d5 0.2000

如果这一步出错呢？

触发条件：把提高TopK当成唯一优化，或让重排只看到错误的Top1。

只传融合Top1=d3给重排 → d2和d4都不在输入 → 再好的排序也无法选中它们；仅看答案流畅会把专业版30天错套标准版。

恢复方法：先判断相关块是否进入候选池：没进则查查询、切分、过滤和召回；已进但靠后再查融合与重排。记录相同样本下的质量、成本和耗时，避免只选成功例。

6.2 Re-ranking重排

为什么需要Re-ranking？

你有没有遇到过这种情况：Google搜索前10个结果里，最有用的那个藏在第7位？Re-ranking就是为了解决这个问题！

核心问题： 检索出来的chunks并不一定完全和问题相关，直接提交给LLM可能导致：

  • 生成结果质量不佳
  • 包含无关信息
  • 浪费token成本

解决思路：借鉴推荐系统的做法

粗排（Coarse Ranking）：基于Embedding快速筛选
    ↓
精排（Fine-grained Ranking）：专门的排序引擎深度评分
    ↓
Top-K选择：挑选最相关的内容

ColBERT（Contextualized Late Interaction over BERT）是一种快速准确的检索模型：

核心创新：

补充说明：ColBERT 的文档表示可以离线建立，当前查询的向量仍需在线计算。MaxSim 是对每个查询 token 寻找文档 token 的最大相似度后汇总，不等于把所有查询预先算好。

传统Cross-Encoder：
Query + Doc → BERT → Score

ColBERT：
Query → BERT → Q_vectors (预计算)
Doc → BERT → D_vectors (预计算)
Score = MaxSim(Q_vectors, D_vectors) （快速计算）

性能对比：

检索10K文档：
    Cross-Encoder: ~5秒
    ColBERT: ~50毫秒
速度提升：100倍！

实战：构建高效的Re-ranking Pipeline

补充说明：这段属于依赖外部服务的流程示意，未提供已填充的检索库和完整环境。旧式导入及 get_relevant_documents 需要按锁定版本迁移，不能把构造对象视作运行成功。

from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain_cohere import CohereRerank
from langchain.retrievers import ContextualCompressionRetriever

#步骤1：初始向量检索（粗排）
vectorstore = Chroma(
    collection_name="rag_collection",
    embedding_function=OpenAIEmbeddings()
)
base_retriever = vectorstore.as_retriever(
    search_kwargs={"k": 50} # 初始召回50个
)

#步骤2：Cohere重排（精排）
reranker = CohereRerank(
    api_key="your_api_key",
    model="rerank-english-v3.0",
    top_n=5 # 最终返回5个
)

#步骤3：组合成压缩检索器
compression_retriever = ContextualCompressionRetriever(
    base_compressor=reranker,
    base_retriever=base_retriever
)

#步骤4：执行查询
query = "如何优化RAG系统性能？"
compressed_docs = compression_retriever.get_relevant_documents(query)

#结果：从50个候选中精选出5个最相关的文档
for i, doc in enumerate(compressed_docs):
 print(f"排名 {i+1}: 相关度分数 {doc.metadata['relevance_score']:.3f}")
 print(f"内容预览: {doc.page_content[:100]}...")

Re-ranking的性能指标

评估指标：

  1. NDCG@K (Normalized Discounted Cumulative Gain)
DCG@K = Σ(rel_i / log2(i+1))
NDCG@K = DCG@K / IDCG@K

rel_i：第i个位置文档的相关性
完美排序时NDCG = 1.0

  1. 补充说明：计算 MRR 时，无相关命中的查询倒数排名记为 0，并明确查询数量；Recall@K 的分子应为前 K 个候选中的相关资料数，分母为该查询全部已标注相关资料数。

    MRR (Mean Reciprocal Rank)
MRR = 1/N * Σ(1/rank_i)

rank_i：第一个相关文档的排名
  1. Recall@K
Recall@K = (相关文档数) / (总相关文档数)

Re-ranking最佳实践建议

  1. 选择合适的方法
预算充足 + 追求极致性能 → Cohere Rerank 3
需要本地部署 → ColBERT / SentenceTransformer
中文场景 → BGE Reranker
预算有限 + 简单场景 → RRF融合
  1. 设置合理的K值
粗排Top-K：50-100（召回率优先）
精排Top-N：3-10（精确度优先）

原则：
K太小：可能漏掉相关文档
N太大：浪费LLM上下文窗口
  1. 混合策略
第一阶段：向量检索 (Top-100)
第二阶段：RRF融合 (Top-50)
第三阶段：Cohere Rerank (Top-10)
第四阶段：LLM生成

这样既保证召回，又控制成本
